GeoParquet: Parquet that knows where things are

Yesterday, DuckDB read a GeoJSON file as a table. Today the file format itself carries the location: GeoParquet is the Parquet you met in Lesson 14, plus a geometry column and a little geo metadata in the file footer. Same columnar, compressed file — now it knows where every row is.

The code

from shapely.geometry import Point
import geopandas as gpd

stations = gpd.GeoDataFrame(
    {"station_id": ["NYC-01", "PHL-01", "BOS-01"],
     "city": ["New York", "Philadelphia", "Boston"]},
    geometry=[Point(-74.006, 40.7128),
              Point(-75.1652, 39.9526),
              Point(-71.0589, 42.3601)],
    crs="EPSG:4326")

stations.to_parquet("stations.parquet")  # writes GeoParquet
back = gpd.read_parquet("stations.parquet")

to_parquet on a GeoDataFrame does not just dump a table: it writes the geometry column as WKB (Well-Known Binary) and adds a geo metadata entry to the Parquet footer declaring which column holds the geometry, the coordinate reference system (EPSG:4326, lon/lat), and the dataset bounding box. read_parquet reads that metadata back, so back is a GeoDataFrame again — geometry and CRS intact, not a plain table with a mystery binary column.

In practice

This is the file format a geospatial data lake is built on. A data engineer writes station locations, storm tracks, or county polygons to GeoParquet because it keeps everything Parquet already gave you — columnar storage, compression, and reading only the columns you need — and adds spatial awareness: engines can skip whole row groups whose bounding box cannot match your query, and any Parquet reader (DuckDB, Spark, GeoPandas) can open the file even if it ignores the geometry. One format, from laptop exploration to the lake, with no sidecar files to lose track of.

Python bridge: it is exactly df.to_parquet() from pandas — except a GeoDataFrame carries the geometry and CRS along for the ride. If you have ever saved a pandas DataFrame to Parquet, you already know the call; GeoParquet just means the location column survives the round trip as real geometry.

Try it

Practice question: read stations.parquet back with gpd.read_parquet, then keep only the stations north of latitude 40 and print their station_id and city. (Hint: a point geometry's latitude is geometry.y.)

Show answer 
back = gpd.read_parquet("stations.parquet")
north = back[back.geometry.y > 40]
print(north[["station_id", "city"]])

Result: two rows — NYC-01, New York (latitude 40.7128) and BOS-01, Boston (latitude 42.3601). Philadelphia (39.9526) drops out, since it sits just south of latitude 40.
